## Question 

Differentiate syntax, semantic, linker, runtime, and logical errors.

## Answer 

Programming errors differ based on when they occur (the lifecycle phase), why they happen, and how the system responds. 
Here is a direct comparison of syntax, semantic, linker, runtime, and logical errors:

| Error Type | Phase Detected | Cause | System Behavior | Code Example |
|---|---|---|---|---|
| Syntax | Compile / Parse | Violating grammar rules of the language. | Halts compilation; fails to build. | int x = 5 (missing semicolon) |
| Semantic | Compile | Grammatically correct but meaningless to the compiler. | Halts compilation; throws type/meaning errors. | x + y = z; (assigning to an expression) |
| Linker | Linking | Missing or mismatched external references/libraries. | Halts executable generation after compilation. | Calling void Main() instead of main() |
| Runtime | Execution | Illegal operations attempted during program run. | Crashes the program or throws exceptions. | int result = 10 / 0; (division by zero) |
| Logical | Post-Execution | Flaw in the algorithm or business logic. | Runs perfectly to completion but outputs wrong results. | if (a = b) (accidental assignment instead of comparison) |

### Detailed Breakdown

### 1. Syntax Errors
Syntax errors occur when the source code breaks the grammatical rules of the programming language. The compiler or interpreter cannot parse the code structure, so it stops immediately before any machine code or bytecode is generated.  

* Common Causes: Missing parentheses, typos in keywords, unclosed quotation marks, or missing semicolons. 

### 2. Semantic Errors
Semantic errors happen when the code follows perfect grammar rules, but the statement makes no contextual sense to the machine. 

* The Analogy: Think of the English sentence "The triangle is pregnant." The grammar is perfectly correct (Noun + Verb + Adjective), but the meaning is fundamentally impossible.
* Common Causes: Assigning a value to a literal or expression (e.g., 10 = x;), or performing operations on mismatched data types without type casting.  

### 3. Linker Errors
Linker errors occur after successful compilation of individual code files, during the phase where the linker tries to glue all object files and external libraries together into a single executable.  

* Common Causes: The compiler compiled a function call successfully based on a prototype, but the linker cannot find the actual body of that function in any of the connected files or libraries. This often happens with misspelled main() functions or missing library bindings. 

### 4. Runtime Errors (Exceptions)
Runtime errors are bugs that survive the build phase but blow up while the program is actively running. The syntax is correct, the meaning is clear, and the linking is fine, but the computer hits a physical or mathematical impossibility at execution time. 

* Common Causes: Dividing by zero, running out of RAM, trying to open a file that does not exist, or index out-of-bounds errors. 

### 5. Logical Errors
Logical errors are the trickiest to catch because the computer sees nothing wrong with the code. The code builds, links, runs cleanly, and terminates without crashing—but it produces the wrong output because the programmer's math or logic was flawed. 

* Common Causes: Using the wrong formula (e.g., subtracting instead of adding), using the wrong comparison operators, or creating unintended infinite loops.

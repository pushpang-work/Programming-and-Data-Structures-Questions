## Question 

Describe preprocessing, compilation, assembly, linking, and loading.

## Answer 

The transition from human-readable source code to a running program involves five distinct stages: preprocessing, compilation, assembly, linking, and loading.
Here is the breakdown of how code travels from your text editor into the system's memory:

<pre>
[ Source Code (.c / .cpp) ]
            │
            ▼
      Preprocessing      <── Resolves directives (#include, #define)
            │
            ▼
     Compilation Proper  <── Translates high-level code to assembly
            │
            ▼
         Assembly        <── Translates assembly to machine object code
            │
            ▼
         Linking         <── Combines object files & libraries into binary
            │
            ▼
         Loading         <── Places binary into RAM & executes it
</pre>

### 1. Preprocessing
The preprocessor is a text-substitution tool that clean-ups and prepares the source code before the actual compilation begins. It scans the file for directives starting with a # symbol. 

* Header Inclusion: Replaces #include lines with the actual content of the specified header files. 
* Macro Expansion: Replaces macro names (defined via #define) with their literal values or code snippets throughout the file.  
* Comment Removal: Strips all comments (// and /* ... */) out of the file since the machine doesn't need them. 
* Conditional Compilation: Evaluates directives like #ifdef or #ifndef to include or exclude specific blocks of code. 
* Output: Generates an expanded intermediate source file (typically with a .i or .ii extension). 

### 2. Compilation
The compiler takes the expanded text file from the preprocessor and translates it into a lower-level language. 

* Syntax & Semantic Analysis: Checks the code against the language rules to catch syntax errors, structural mistakes, and type mismatches. 
* Optimization: Rearranges or streamlines the code to ensure it runs as efficiently as possible on the target hardware.  
* Output: Translates the code into architecture-specific assembly language (typically a .s or .asm file). Assembly language uses short mnemonic codes (like MOV, ADD, PUSH) tailored to the specific CPU structure. 

### 3. Assembly
The assembler translates the human-readable assembly instructions into the language the computer hardware actually executes. 

* Binary Translation: Converts the mnemonic assembly instructions into binary machine code (0s and 1s).
* Symbol Tables: Builds initial symbol tables to keep track of variable and function labels.
* Output: Creates a relocatable object file (typically .o or .obj). This file contains pure machine code, but it is not yet executable because it lacks memory addresses and references to external functions. 

### 4. Linking
The linker takes one or more independent object files and glues them together with external dependencies to create a finished product. 

* Symbol Resolution: If your code calls a function defined in another file or a system library (like printf), the linker matches the call to its exact definition.
* Memory Relocation: Combines all the text and data segments from the separate files and maps out their final relative memory addresses. 
* Static vs. Dynamic Linking:
* Static Linking embeds the library code directly inside the final binary file.
   * Dynamic Linking leaves hooks in the file to point to shared system libraries (like .so or .dll files) that will be hooked up later. 
* Output: Produces a single, self-contained executable file (like a .exe or an ELF binary). 

### 5. Loading
The loader is a component of the operating system that transitions the program from a passive file on your storage drive to an active process in memory. 

* Memory Allocation: Allocates space in physical RAM and sets up the segment structures for the program's code, global data, stack, and heap.
* Dynamic Resolution: Finishes any dynamic linking by finding and loading required shared libraries into memory.
* Execution Start: Copies the program's instructions into RAM, points the CPU's instruction pointer to the program's entry point (usually the main function), and hands over execution control.
